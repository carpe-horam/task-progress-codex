# 接入来源隔离

来源为 codex、cindy、dsh，指宿主而非模型。Cindy 内运行 Codex 模型仍属于 Cindy。任务共用本机服务，但列表、搜索、分页、计数及实例详情限定在同一来源。

## 登记与存量

桥接发送 `X-Task-Progress-Source`：Codex 默认 codex，Cindy 随包桥固定 cindy，DSH 启动桥时设置 dsh。成功的、返回准确 session_id 的任务操作将归属写入独立 `<session_id>.source.json`（version 1），不改任务结果。已登记来源不可被另一宿主覆盖，有明确来源的会话拒绝其他来源的显式读写及归档请求。

Cindy 启动和每分钟复用归档对账队列读取的确认 KV 快照，按明确的 host→session 映射分批登记来源，每批最多100个。私有 RPC `task-progress/register-source` 不在 Agent 工具中，浮窗不能调用。批次失败或回执不完整时下轮重试；缺失目标不创建空任务，来源冲突不覆盖。来源登记不代表归档或任务完成。

没有来源证据的旧记录为 unknown，不因缺少 Cindy 绑定就被分给 Codex；不根据标题、模型或年龄推断归属。unknown 只在显式“来源待确认”列表查看，不混入已分类来源。来源与任务不是跨文件事务：任务成功而来源登记失败时不自动重放任务写入，未确认归属的记录保持 unknown，后续明确宿主操作或绑定登记可以恢复。clear_progress 后的残留来源文件不会产生目录项。

## 浮窗

`/widget/open` 将 source 固定在只读令牌里，同一实例的不同来源令牌不复用；不能靠查询参数改来源，也不能通过详情 RPC 越过来源读取其他会话或历史实例。无来源的兼容 API 调用，若有明确选中任务则按已登记来源定位；没有选中任务时只进入 unknown，不聚合全盘。

Codex 随包脚本默认 codex；Cindy prepare 生成默认 cindy 的入口。独立脚本与 DSH 需明确正确的 `--source`。本机通用独立入口若不预设来源，必须依靠明确选中的会话推导来源；无选中会话时仍只进入 unknown。回执返回来源，界面标题分别显示 Codex、Cindy、DeepSeekRuntime 或“来源待确认”。来源不匹配报错，不降级到混合列表。

这是共享用户服务内的来源隔离，不是不同系统账号的安全边界；可信管理端持有本机管理凭据时仍可明确登记来源。升级必须同时更新桥和服务，旧桥不携带来源时不会自动归类。

## 同版本共享服务

Cindy 和独立 Codex 的安装包存在宿主适配差异，不能仅因版本相同就相互接管运行中的服务。健康回执提供 `runtime_host` 和 `runtime_compatibility`：后者计算共享协议及执行核心文件的内容摘要，并仅规范化 Cindy 生成时的 manifest 路径替换。

同版本时，Codex/DSH 仅复用经过鉴权且核心摘要一致的 Cindy 服务；摘要缺失、不一致或运行宿主不是 Cindy 时仍执行安装核对。Cindy 自身仍核对同版本内容更新，较新兼容版本的原复用规则保持不变。界面和桥接适配文件不属于核心摘要，由 Cindy 的安装核对保证更新。此策略避免两端交替连接反复替换同版本服务和失效已有浮窗令牌。

## 验证范围

真实 HTTP 覆盖混合来源、同标题、来源固定令牌、跨源详情和归档拒绝、分页计数、重启持久化、明确存量绑定登记、幂等、冲突及缺失目标。真实 Codex/Cindy forward 函数连接隔离服务，核对桥的来源标记。

Chrome 在同一服务创建 Codex、Cindy、unknown 三组任务，验证各自目录、计数及归档不互串，保留会话去重、历史、导出、平铺和滚动回归。Cindy 宿主模型验证明确绑定登记及原归档队列故障路径。上述属于隔离环境测试；本机安装及真实接入验收单独留存，不将源码测试等同于当前运行实例或已发布版本。
