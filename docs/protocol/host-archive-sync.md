# 宿主归档同步

宿主会话归档后，将已绑定的 Task Progress 会话及其所有当前、并行、历史实例归入浮窗历史区。同步是单向的：宿主恢复为 active 不撤销归档，也不重启执行。原任务 JSON、结果、尝试、证据和验收记录不变；即使旧账本仍标 running/open/待验收，也可以归档。

浮窗目录以插件 `session_id` 为最小单位，一会话一行，总数、搜索和分页均按会话计数。行上的 `task_instance_id` 指向当前实例，嵌套 `instances` 保留可明确选择的当前、并行和历史记录；查看记录不会切换 Agent 的前台任务。会话中仍有未结束的非历史实例时，当前实例完成也不会把整个会话从“未完成”筛选中隐藏。宿主归档标记覆盖整会话，包含标记写入后新建的实例；归档不等于完成验收，也不会减少“全部任务”的会话总数。

## Cindy 适配器

`cindy/main.js` 使用已有 `taskProgressSessionsByHostSession` 关联，不把宿主 ID 当作插件 ID，不按标题推断。处理 `did-session-archived`，以及 `did-task-state-changed` 中明确的 `archived` 状态。无需当前聚焦或启用自动验收。

启动时先恢复插件 KV 中的 `taskProgressHostArchiveOutbox`，再检查 `cindy.sessionStates` 是否存在，按每批最多 100 个已绑定宿主 ID 对账。每 60 秒再对账，事件报告 `dropped` 时也触发对账。仅接受身份和数量完整匹配的成功响应；`active`、`deleted`、`out_of_scope`、失败或不支持不会创建新的归档依据，也不会清除已有队列。旧宿主缺少查询方法时仍会恢复持久队列和处理实时事件，但不能声称已补齐未知存量。

发送前重读绑定，过期的待同步项不会改投新目标。成功回执在本进程去重，服务端在重启后仍幂等；瞬时失败保留待同步项并在后续对账重试。每次刷新遇到发送失败时将该项移到队尾，避免坏任务永久阻塞其他任务，并在本次刷新停止后续发送以控制断网超时开销。失败的宿主查询批次保持未知，不妨碍后续批次处理；下轮重新查询失败批次。60 秒重试定时器独立于可选的 `sessionStates`，旧宿主的已观察归档事件也能自动重试。

### 持久化发送队列

队列按 `host_session_id:session_id` 去重，每项保存 version=1、准确的两个 ID 和首次 observed_at。实时事件和存量扫描均先通过现有串行 KV 写入通道确认持久入队，再发送归档请求。成功回执后才从持久队列移出；写入失败、超时或回执不明确不算入队成功，也不授权发送。原有 KV 不确定写入隔离仍有效，不以重读绕过隔离，也不覆盖其他插件字段。

服务回执必须包含布尔 `ok === true`、完全匹配的 session_id 和布尔 archived=true；其他类型的真值、缺失或错误身份都保留待办。清理已保存但确认迟到时遵循原 KV 隔离，重启后以持久队列实际状态恢复。

插件重启后即使宿主已变为 active，仍会按已持久保存的归档依据重试。绑定不再匹配时保留原队列项并标记 binding_changed，不删除、不改投新目标。清理队列失败时原项留存；若服务先前已成功，重启后再次发送由服务幂等处理。每个目标在一轮对账中最多发送一次。

同一运行时已经收到成功确认的项，只要原队列记录仍匹配，即使绑定随后变化也可完成清理；未确认项不享有此例外。观察时间变化时刷新内存项并丢弃旧确认，避免阻塞其他任务。并发事件在本运行时串行处理；重启或不确定回执允许重复 RPC，保证的是服务归档效果幂等，不是发送恰好一次。

仅在内存观察到、尚未获得存储成功确认的事件，仍不能保证在存储本身失败且进程崩溃时保留；成功入队的事件不再依赖宿主当前仍为 archived。

绑定读取与服务写入位于不同存储，不具有跨进程原子事务；发送前核对不是宿主身份认证或跨存储 CAS。队列沿用插件整文档 KV 和本进程串行写通道，不宣称对共享同一 KV 的多个旧运行时具备跨进程 CAS 或防覆盖能力。缺少映射或宿主范围外记录不会被猜测归档。

本次验收按用户要求限定为单 Agent，覆盖运行时内并发回调和该 Agent 崩溃重启。多个不同 Agent 同时写同一 KV 的双适配器模型已排除，其历史复现作为范围外记录保留，测试标为 skip，不作为验收阻塞项或通过项。不提供多个运行时共享 KV 的事务保证。

## 服务持久化与展示

适配器使用独立 JSON-RPC 方法 `task-progress/archive-host-session`，参数为插件 UUID `session_id`、已绑定的 Cindy `host_session_id` 和 `source:"cindy"`。这是认证本机服务上的适配器方法，不在 Agent 工具清单中，不支持取消归档。只读浮窗 RPC 白名单拒绝此方法。不存在的任务、额外参数及冲突的归档来源均拒绝，不创建空任务。

服务在会话锁内原子写入 `<session_id>.host-archive.json`，保存来源、宿主 ID、首次观察时间和原因。该文件独立于任务与排序文件，因此普通任务写入不会撤销归档，也不会改变任务更新时间、执行状态、结果指纹或历史证据。

浮窗目录缓存同时观察任务文件和归档文件。一个会话的所有实例都标记 archived；快照继续可读并返回归档来源。任务仍按原结果显示，归档不意味着完成验收或停止进程。
