# Task Progress 0.2.3

发布日期：2026-10-30 · [本版 README](https://github.com/carpe-horam/task-progress-codex/blob/v0.2.3/README.md) · [完整更新记录](https://github.com/carpe-horam/task-progress-codex/blob/v0.2.3/CHANGELOG.md) · [0.2.2 发布说明](https://github.com/carpe-horam/task-progress-codex/blob/v0.2.2/docs/releases/0.2.2.md)

修复 0.2.2 中 Codex 启动 MCP 桥接时未展开插件路径变量、导致任务进度工具无法加载的问题。新版使用插件目录作为工作目录，启动桥接脚本。

本版附带离线交互手册 `task-progress-0.2.3-guide.html`，内嵌本版界面与合成演示数据。

## 首次安装

需要支持插件与 stdio MCP 的 Codex，以及 Codex 进程 PATH 中可通过 `python` 启动的 Python 3。安装后重启 Codex：

```sh
codex plugin marketplace add carpe-horam/task-progress-codex --ref v0.2.3
codex plugin add task-progress@task-progress-codex
```

## 从旧版本升级

固定旧标签的 Marketplace 执行 upgrade 会继续使用旧标签。重新登记本次发布标签并安装：

```sh
codex plugin marketplace remove task-progress-codex
codex plugin marketplace add carpe-horam/task-progress-codex --ref v0.2.3
codex plugin add task-progress@task-progress-codex
```

重启 Codex 以加载新版插件；首次连接会自动更新共享服务，任务数据无需迁移。已打开的旧面板需要重新打开。

## 验证与限制

修复的启动配置在 macOS 上通过 Codex CLI app-server 工具发现和资源读取验证；两个客户端各发现 26 个工具。测试不创建聊天，也不等同于 Codex 桌面端面板的端到端验收。Linux 与 Windows 的原生安装、登录恢复和升级尚未在对应平台实测。

另一次独立 HTTP 探针未发现工具，日志显示 OAuth 元数据发现请求失败；原因未确认。安装版通过的是插件 stdio 桥接与本机共享服务的路径，而非该独立 HTTP 探针。

0.2.2 已披露的报告回归问题仍未解决：失败根节点状态断言实际得到“待汇总验收”，而不是“执行失败”；该失败在旧版 main 基线也可复现，本次未修改报告行为。
