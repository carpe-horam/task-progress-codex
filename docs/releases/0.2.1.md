## 本次更新

- **精确移交验收**：新增 `handoff_request`，逐项绑定来源并行请求的全部未解决叶到承接叶的 `task_instance_id/epoch/task_id/attempt_id`。承接属于同一会话，可以在当前任务、旧计划或已归档实例中；来源从未启动就取消的叶允许 `attempt_id=null`。已经验收的历史承接也可事后补录。
- **验收后自动对账**：承接仍运行或待复核时，来源继续可见。后续正常写入仅在所有精确承接叶真实 `finished/resolved`、具有证据且子智能体提交已由主会话接受时，冻结独立的移交验收记录并归档来源。登记不启动执行；错误/旧 attempt、遗漏叶、自指、循环移交以及运行中/待复核来源不能闭环。
- **父级判断继续或收尾**：全部子项结束（包括 cancelled/open/failed）且没有待复核提交时，未验收父级显示“待汇总验收”。主会话用 `review_task_closure` 追加 `continue` 或 `accept`：继续则明确重试/重规划，接受则为本次收尾保留独立验收。全部子项 resolved、父级仍 pending 时，继续使用原有成功综合验收流程。
- **原结果与历史保留**：移交或接受收尾不把 open/cancelled 改成 resolved，不放行要求 resolved 的依赖。原节点、attempt、submission、review 和历史计划保持可查。来源显式 retry 可以重新出现，旧归档与承接验收证据保持冻结。来源 epoch 与结果指纹防止迟到决定；相同 ID、相同内容的跨秒重放不重复生效，reviewer 配置变化仍被拒绝。
- **UI 与报告审计**：历史任务同时显示已解决和已结束计数，取消不算成功。UI、独立 HTML 与 XLSX 报告保留移交映射、精确承接尝试、验收证据和收尾决定。模型可用选择性历史查询读取 `handoffs`、`handoff_closures` 与 `closure_reviews`，普通写入仍只回小回执。

## 首次安装（macOS）

需要 Python 3，以及支持插件、Streamable HTTP 和 `http_headers_helper` 的 Codex CLI/客户端。命令固定使用本次发布标签：

```sh
codex plugin marketplace add carpe-horam/task-progress-codex --ref v0.2.1
codex plugin add task-progress@task-progress-codex
python3 "${CODEX_HOME:-$HOME/.codex}/plugins/cache/task-progress-codex/task-progress/0.2.1/service_manager.py" install
```

三条命令全部完成后，**重启 Codex**。前两条安装插件，最后一条安装并启动本机后台服务；重启后重新发现 `handoff_request` 和 `review_task_closure`，旧会话可能仍缓存原工具清单。只刷新面板不能完成工具升级。请使用稳定安装的 Python 3，服务保存其解释器绝对路径。

## 从旧版本升级

已有 `task-progress-codex` Marketplace 时，重新登记到 `v0.2.1`，再安装插件与服务：

```sh
codex plugin marketplace remove task-progress-codex
codex plugin marketplace add carpe-horam/task-progress-codex --ref v0.2.1
codex plugin add task-progress@task-progress-codex
python3 "${CODEX_HOME:-$HOME/.codex}/plugins/cache/task-progress-codex/task-progress/0.2.1/service_manager.py" install
```

随后**重启 Codex**，加载新工具和界面。移除的是 Marketplace 登记；任务数据独立保存在本机缓存中，无需迁移。仅更新 Marketplace 不会更新已安装插件或后台服务；仅更新服务也不能确保已有客户端已重新加载工具。尚未登记 Marketplace 的用户使用首次安装命令。

检查插件与服务：

```sh
codex plugin list
python3 "${CODEX_HOME:-$HOME/.codex}/plugins/cache/task-progress-codex/task-progress/0.2.1/service_manager.py" status --json
```

本地源码安装和服务管理见[安装文档](https://github.com/carpe-horam/task-progress-codex/blob/v0.2.1/docs/installation.md)。自动后台管理当前支持 macOS；Linux 需自行配置用户服务，Windows 尚未验证。

## 使用与证据边界

可以告诉 Codex：“检查已结束的并行任务；先验收取消或移交结果，决定继续还是收尾归档，保留原始结果和历史。”主会话读取真实结果后负责登记移交与验收；新接口不会推断请求之间的语义关系，也不会把相似标题当作移交证据。

Task Progress 保存主会话的判断并校验插件内状态。它不会自动创建、唤醒或控制宿主 agent，不会停止外部执行者，也不能强制其他工具遵守计划。角色、agent ID 和模型配置由调用方填报，HTTP 凭据不证明主/子会话身份。实际全屏、内联和标签页展示由 Codex 宿主决定。

手册使用真实界面与合成演示数据，不证明真实宿主展示或 agent 调度。导出包含本次新增的移交/收尾审计；独立请求队列与恢复上下文仍通过 API 读取。旧 SQLite 以有界只读摘录展示，不补造验收。0.2.0 的历史发布说明和截图标签保持原样。
