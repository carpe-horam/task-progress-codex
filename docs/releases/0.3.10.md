# Task Progress 0.3.10

Cindy、Codex 和 DeepSeekRuntime 统一版本 **0.3.10**。

- Cindy 宿主会话归档后，已绑定任务的当前、并行、历史及后来创建的实例一起进入浮窗历史区；宿主取消归档不会恢复任务。
- 启动时检查已有绑定，每分钟补齐遗漏；归档请求先持久入队，失败、回执丢失或插件重启后继续重试。允许重复发送，服务归档效果幂等。
- 浮窗以会话为最小单位：列表、搜索、分页和总数去重，保留会话内的任务记录选择。归档保留数据，不会减少“全部任务”的会话数，也不代表执行完成或验收通过。
- Cindy、独立 Codex 与 DeepSeekRuntime 按接入宿主隔离列表、总数、详情与归档请求。Cindy 中使用 Codex 模型仍属于 Cindy；缺少来源证据的旧任务保留在“来源待确认”，不猜测归属。
- 同版本且共享核心兼容时，Codex/DSH 复用 Cindy 服务，避免交替重连反复切换服务和使浮窗令牌失效。

## 升级

本版为源码 Release，无附加安装资产。Codex 按[安装说明](../installation.md)重新登记 Marketplace 到 `v0.3.10` 并安装；Cindy 从同一标签按[构建说明](../../plugins/task-progress/cindy/README.md)生成，DeepSeekRuntime 同步使用该版本。

桥接入口与共享服务需一起更新。来源只在新版入口的明确调用或 Cindy 保存的绑定中确认，旧桥不会自动补齐所有未知任务。已有浮窗和长驻客户端需要重新连接才能使用新入口。

## 验证边界

覆盖单 Agent 内重复事件、失败重试、绑定变化、确认后清理失败、持久入队后的进程退出/SIGKILL恢复，以及真实隔离 HTTP 与 Chrome 页面。多个独立 Agent 同写一份 Cindy KV 不在本版保证范围内；没有断电持久化保证。

本机开发验收另行验证了已安装 Cindy 插件/worker、真实独立 Codex app-server/MCP、页面来源隔离、会话归档范围及交替重连稳定性。没有通过真实用户会话的宿主归档按钮触发测试，也没有强制重启已有 Codex 桌面进程。DeepSeekRuntime 此次只做源码/打包回归；未增加其宿主归档适配器。

原有任务结果及验收记录保留。回滚需同时恢复桥、共享服务与入口，先停止新版调用；默认保留数据与新增 sidecar，避免覆盖期间新进度。
