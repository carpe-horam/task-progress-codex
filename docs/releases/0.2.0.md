# Task Progress 0.2.0

发布日期：2026-10-28 · [本版 README](https://github.com/carpe-horam/task-progress-codex/blob/v0.2.0/README.md) · [完整更新记录](https://github.com/carpe-horam/task-progress-codex/blob/v0.2.0/CHANGELOG.md)

新版自包含交互手册可从本 Release 的 `task-progress-0.2.0-guide.html` 附件下载并在浏览器打开；在线 GitHub Pages 会在 PR 合并并部署后更新。

0.2.0 把多阶段工作的规划、执行、恢复和验收放到同一份可追踪记录中，面板先展示进度与摘要，需要时再打开细节。

- **先做粗规划**：记录主要阶段、依赖和分工，执行中再补充；插件内未规划的空根任务不能开工。只有拆出至少两个独立结果边界才分组；只有一项时保留原任务并补充摘要、依赖。
- **排队与并行**：主会话判断独立请求的去处，排队请求显式激活，并行工作使用隔离实例；完成一项插入工作后继续检查原任务和队列。
- **恢复与重规划**：保存原文、目标、约束、验收条件与恢复位置；同一目标继续推进，调整计划保留理由、旧轮次和证据。
- **独立验收**：分别记录计划分工、派发绑定、子智能体提交及主会话复核。待复核不放行依赖，接受 open 报告仍是未解决；叶任务 100% 后仍需根综合验收。
- **按需读取**：写入只回身份和状态；概览、节点、记录、上下文和历史显式读取。面板独立轮询，HTML/XLSX 导出所选任务执行历史。
- **简洁界面**：动态层级编号、摘要优先、详情折叠，排队数量可见；顶部只保留计划轮次与主会话模型，等待时钟居中。并行任务以同级根展示，百分比只统计主任务。
- **并行结果归档**：只有主会话将并行根综合验收为 resolved 后，才从当前网络移入历史；open、failed、cancelled 保留当前。显式 retry 会重新激活，并保留旧完成记录。
- **共享本机服务**：同一操作系统用户的 Codex 会话连接一个认证 HTTP 后台进程，任务继续按会话隔离；macOS 安装器提供健康检查与升级失败回滚。

## 首次安装（macOS）

需要 Python 3，以及支持插件、Streamable HTTP 和 `http_headers_helper` 的 Codex CLI/客户端。以下命令固定使用本次发布标签，不依赖 `main` 是否已合并：

```sh
codex plugin marketplace add carpe-horam/task-progress-codex --ref v0.2.0
codex plugin add task-progress@task-progress-codex
python3 "${CODEX_HOME:-$HOME/.codex}/plugins/cache/task-progress-codex/task-progress/0.2.0/service_manager.py" install
```

运行后**重启 Codex**。前两条安装插件，最后一条安装并启动用户后台服务；仅添加插件还不够。使用稳定安装的 Python 3，服务会保存解释器的绝对路径。

## 从旧版本升级

已有 `task-progress-codex` Marketplace 时，移除旧登记并从本次发布标签重新添加，再安装插件与服务：

```sh
codex plugin marketplace remove task-progress-codex
codex plugin marketplace add carpe-horam/task-progress-codex --ref v0.2.0
codex plugin add task-progress@task-progress-codex
python3 "${CODEX_HOME:-$HOME/.codex}/plugins/cache/task-progress-codex/task-progress/0.2.0/service_manager.py" install
```

完成后**重启 Codex**，释放旧版 stdio 会话进程并加载新界面。移除的是 Marketplace 登记；任务数据保存在独立的本机缓存中，无需迁移。尚未登记 Marketplace 的用户使用首次安装命令。仅升级 Marketplace 快照不会更新已安装插件或后台服务。

安装后可检查插件与服务：

```sh
codex plugin list
python3 "${CODEX_HOME:-$HOME/.codex}/plugins/cache/task-progress-codex/task-progress/0.2.0/service_manager.py" status --json
```

本地源码安装与服务管理详见 [本版 README](https://github.com/carpe-horam/task-progress-codex/blob/v0.2.0/README.md#安装)。自动后台管理当前支持 macOS；Linux 需自行配置用户服务，Windows 尚未验证。

## 使用与证据边界

安装后可以告诉 Codex：“按依赖拆分这项工作，持续更新进度，提交后单独验收。” skill 约定先规划，hooks 经宿主信任后提供非阻断提醒。首次粗规划后请求一次进度页；普通更新不重复打开，关闭后按用户要求重开。

Task Progress 保存主会话的决策并校验自身状态转换。它不会创建子智能体、唤醒闲置会话或强制其他工具遵守计划。角色、agent ID 和模型配置由调用方填报，HTTP 凭据不证明主/子会话身份。全屏、内联和标签页的实际展示由 Codex 宿主决定。

交互手册与预览采用本版界面及合成演示数据，说明操作和状态含义，不作为真实宿主或实际 agent 调度的证明。旧工具消息不会追溯缩小，已打开的旧 iframe 需重开。当前 HTML/XLSX 不包含独立请求队列与恢复上下文，这些信息通过 API 持久读取；旧 SQLite 只读摘录不补造验收。
