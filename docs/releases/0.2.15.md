# Task Progress 0.2.15

发布日期：2026-11-03 · [完整更新记录](https://github.com/carpe-horam/task-progress-codex/blob/v0.2.15/CHANGELOG.md)

- **执行失败自动收尾**：新增托管命令入口，由独立监督进程保存退出码与终态；MCP 进程结束或重启后可继续对账。外部 Dagu/子代理运行使用结构化回执接入，失败、阻塞与取消分别保留。
- **每轮执行可追溯**：一个 attempt 最多绑定一个 run，重跑必须创建新 attempt；旧 run ID 不能复用到新尝试，迟到或冲突回执不会改写当前结果。
- **收尾写入可恢复**：错误 attempt 的终态写入留下拒绝审计、当前身份和恢复动作；未知 attempt 的收尾被拒后，服务端阻止继续更新或启动新执行，直到如实收尾。
- **长任务拆分门禁**：HTN 叶任务超过 10 分钟后，继续运行更新或绑定执行前须分解或提交结构化复核。保留单一结果的决定绑定 attempt/执行、最多有效 10 分钟，摘要“无需拆分”不能豁免。
- **界面与导出**：区分执行中、执行成功待收尾与收尾写入待恢复；面板、HTML 和 Excel 保留各轮执行身份及重试历史。

## 安装或升级

```sh
codex plugin marketplace remove task-progress-codex
codex plugin marketplace add carpe-horam/task-progress-codex --ref v0.2.15
codex plugin add task-progress@task-progress-codex
```

首次安装可省略第一行。安装后重启 Codex，重新发现新增工具并更新共享后台；现有任务数据保留。重启前保存进行中的工作。详见[执行生命周期协议](../protocol/execution-lifecycle.md)和[安装文档](../installation.md)。

## 验证与边界

- 294 项 Python 后端回归通过，其中 12 项覆盖新执行生命周期，包括真实监督进程跨 MCP 退出后自动保存失败回执。
- 3 项 Chrome 隔离回归通过：执行生命周期与拒绝恢复、重试徽标、时间生命周期；包含 HTML/Excel 导出。
- 进程成功不自动代表任务验收通过。未接入回执的外部工具无法自动追踪；外部回执为调用方填报，不能宣称宿主认证。
- 不因耗时猜测外部失败，不自动中断实际进程，不改写已有活跃会话的历史事实。Linux/Windows 原生安装与运行未在本次验证。
- 本发布通过 `v0.2.15` 源码标签分发，不包含独立打包资产。
