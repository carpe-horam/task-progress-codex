- 当前 23 个 Task Progress Python 服务：22 个运行目录仍指向 0.1.3，另 1 个为 0.1.4，PID 84244，19:34:07 启动。它与宿主日志中同秒的一次新会话 `task_progress` starting/ready 事件对应；没有得到权威的逐 PID 会话映射。

- 23 个服务的 69 条 stdin/stdout/stderr 管道，均能通过双端地址匹配到父进程持有的对应描述符。宿主仍连接着它们。

- 宿主日志自 19:00 起对 24 个不同会话报告过 Task Progress ready；这些会话的数据库元数据均未归档。这能解释存在多个会话服务，但 ready 事件不等于当前正在执行，也不能把 24 个会话和 23 个 PID 强行一一对应。

## 退出与升级边界

当前插件主循环读取 stdin，EOF 后自然结束。对安装的 0.1.4 新建一个一次性服务进程，只发 initialize 后关闭 stdin，**0.081 秒内以 0 正常退出**。未关闭或终止现有用户服务。此检查支持插件在宿主释放输入后能够正常退出；不证明宿主一定及时释放所有闲置会话。

检查时磁盘上的 0.1.3 缓存目录已不存在，旧的 22 个进程仍驻留且连接宿主。旧目录的独立 EOF 探测因 FileNotFoundError 未运行。不能把 0.1.4 的结果冒充旧进程的实测结果。

因此，目前能够确认的是**旧实例尚未重载**，不能仅凭数量称为泄漏。旧实例在内存中保留已经加载的代码，后续若需要读取旧路径中的 app.html 等文件，可能因目录不存在而失败；本轮没有向现有进程注入请求验证该路径。

要确认“闲置会话服务未回收”，仍需一次受控的会话卸载或宿主正常退出实验，验证对应管道关闭后进程是否退出。本轮没有关闭用户会话、重启宿主或强制清理进程。需要切换全部旧实例时，可在工作保存后正常重启 Codex。
