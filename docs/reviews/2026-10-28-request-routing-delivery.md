# 独立请求、恢复上下文与验收进度交付

2026-10-28。本轮实现用户确认的职责：主会话拆分、编辑、调整和验收；Task Progress 保存可恢复细节并引导下一步。源码位于 `codex/fix-thread-state-compat`，未提交或推送。

## 已实现并安装

- 独立请求可排队或建立并行实例。登记不启动执行，并行叶任务由子智能体完成；待验收和最终结果与当前主任务隔离。
- FIFO 显式激活、未启动请求调整与取消、稳定请求 ID 去重。主任务未收尾不能被队列抢占；切换、归档和队列保存在同一次原子写入中。
- 原始请求、目标、约束、验收标准、恢复位置和修改理由持久保存。重规划保留上下文与历史证据；旧记录未知的信息不补造。
- 会话剩余工作与单个任务结果分开。独立任务结束后引导返回仍活动的主任务，或在其收尾后继续队列；已归档来源与当前返回目标分开保存。
- 主进度按已解决且完成当前验收协议的叶任务计算。待验收、执行中、未开始、未解决单列；产出摘要直接可见，根综合验收单列。
- 并发响应使用同一锁内快照，避免把旧任务进度与新主任务元信息混在一起，迟到响应不能覆盖较新的任务。
- skill 和启动/新消息提醒已加入分流、恢复和结束前检查；明确用户停止优先于处理队列。

## 能力边界

这次完成的是插件状态、分流和恢复协议，不是宿主强制调度。主会话仍须调用接口并如实报告执行；插件不自动唤醒闲置聊天、不自行派发 agent，也不能保证上下文压缩后模型必然调用恢复入口。用户明确停止或取消优先。

结构调整继续使用分解、改派和显式重规划；本轮没有新增任意修改已运行/已验收节点、抢占暂停或优先级调度。当前 HTML/XLSX 导出仍覆盖所选任务的执行历史，队列与恢复上下文通过 API 持久读取；未宣称导出包可完整恢复整个会话队列。
