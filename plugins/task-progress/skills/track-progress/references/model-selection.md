#### 子智能体模型与思考强度选择

以下是结合 [OpenAI 模型选择指南](https://developers.openai.com/api/docs/guides/model-selection) 和 [GPT-6 指南](https://developers.openai.com/api/docs/guides/latest-model) 的派发起点，不是质量保证或固定价格排序。先判断子任务的边界、歧义、跨文件影响、错误代价、验收难度和视觉/界面需求，再考虑速度和成本；简单可验证的部分可以与需要深入判断的部分分别派发。

| 工作性质 | 推荐起点 | 例子 |
|---|---|---|
| 范围明确、结果容易核验的重复工作 | `gpt-6-luna` / `low`；需要在明确约束下综合多处信息可试 `medium` 或 `xhigh` | 提取字段、定点查找、简单改文案、初步分类 |
| 视觉判断、界面操作或边界清晰的局部修复 | `gpt-6.1-terra` / `medium`；简单操作可试 `low`，较复杂的视觉判断可提高到 `high` | 对照截图、操作已知界面、根据明确复现修复局部代码；提供输入和验证方法 |
| 多文件实现、复杂调查或需要综合判断的一般工程工作 | `gpt-6.1-sol` / `medium`；证据冲突、细致评审或高复杂度用 `high` / `xhigh` | 根因分析、跨模块修复、审查和集成验证 |
| 问题高度模糊、关键决策代价高或需要深度综合 | `gpt-6-astra` / `medium`；特别困难或要求严格时用 `high` / `xhigh` | 难以定位的系统性故障、复杂架构权衡、相互矛盾证据的独立评估 |

强度是推理预算而非能力保证：从满足风险的较低档开始，证据不足或验收失败时可提高强度、换更强模型或进一步拆分，再独立核验。`max` / `ultra` 只在宿主明确支持且任务确有必要时考虑；不要假设 API 的可选值就是当前派发工具支持的值。必要时在相同输入、验收标准和强度下比较模型，计入复核和返工时间；以上场景映射是实践建议，模型及产品能力可能变化。

仅在当前宿主允许委派及显式指定模型时应用这些建议；用户、宿主和更高优先级指令优先，实际派发以工具列出的模型 ID、支持的强度和可用性为准。宿主可使用继承默认值，但当前插件启动子智能体 attempt 必须记录明确的模型和强度。若无法如实提供这两项，不猜测、不伪报，按 [HTN 派发](htn-dispatch.md) 的受限流程处理。主会话仍须验收结果，模型选择不扩大授权。
