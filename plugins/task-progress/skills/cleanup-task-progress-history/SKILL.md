# 清理历史 Task Progress 数据

本 skill 只处理用户明确提出的历史数据清理请求，并且只清理已经归档的 Codex 会话。它不是归档监听器，不会在归档事件发生时自动运行；也不因任务完成、开始新任务或切换视图而运行。

## 适用范围

- 目标必须是用户明确指定的、已经归档的 Codex 会话。仅仅废弃、暂时不用或任务已完成的活动会话都不符合清理条件。
- 必须记录用户明确确认“该 Codex 会话已归档”及其与目标插件 `session_id` 的对应关系，或取得宿主提供的等效归档证据。仅提供插件 ID 或提出删除请求不能证明会话已归档；`task_history` 和其中的 `archived_at` 仅说明任务实例归档，不证明 Codex 会话归档。
- 必须取得该会话在 Task Progress 插件中的 `session_id`。Codex thread ID、路径、标题和 Task Progress `session_id` 是不同标识，不得互相猜测或替代。
- 清理接口 `clear_progress` 以整个插件 `session_id` 为边界：会删除该会话的当前任务、`task_history` 中的历史任务、计划轮次、尝试、证据和视图登记。它不支持只删除某个旧任务或只清除 `task_history`。
- 若用户只想删一个历史任务、保留同一会话的当前任务，停止清理并说明当前接口不支持这种粒度；不要调用 `clear_progress`。
- 不扫描磁盘、插件数据库或其他会话来猜测目标，也不清理未明确指定的 `session_id`。

## 清理流程

1. 确认用户明确要求永久清理，并先询问保留期限：“希望保留最近多久的 Task Process 数据？清理早于多少天的已归档会话？”可给出 30、90、180 天或自定义天数供选择。期限未明确前不继续筛选或删除。
2. 取得用户明确列出的插件 `session_id`，并分别记录其对应 Codex 会话的明确归档依据和 ID 对应关系。当前插件没有归档事件、归档状态与 `session_id` 的可信映射，也没有列举全部进度会话的工具，不能独立验证归档状态；用户对具体会话及插件 ID 对应关系的明确归档确认可以作为依据，须如实标注来源为“用户确认”，不能称为插件已验证。若用户只提供 thread ID、标题或插件 ID 而未确认会话已归档，先补齐缺失的插件 ID、归档确认或对应关系；无法补齐就跳过，不以猜测继续清理。只处理用户明确列出的目标。
3. 对每个 ID 先显式查询 overview。概览不含完整年龄依据；清理前确需检查整个会话范围时，显式调用 `get_progress({"session_id":"<目标 session_id>","view":"full"})`，核对当前 JSON 实例的 `updated_at`、归档任务的 `archived_at` 及完整请求登记；并行实例若仅有精简快照，分别指定其 `task_instance_id` 读取 full。也可用 history 分页查归档，以 `expected_state_revision` 固定分页版本，变更时重读。使用用户选定的期限计算截止时间；旧 SQLite 只读摘录不是完整数据库年龄证据，也不在此清理授权内。时间戳缺失或无法解析时，将该会话标为“无法判定”，不要删除。
4. `clear_progress` 会删除整个 `session_id` 的数据。只有当该 Codex 会话已归档、且其当前任务和所有历史任务都早于截止时间时，才把它列为候选。只要会话未归档、任一条记录较新，或无法确认归档状态，就跳过整个会话；不得为了删除其中的旧任务而连较新的记录一起删除。
5. 先向用户展示候选 `session_id`、已归档状态依据、判定使用的时间戳、截止时间和将删除的完整范围，并询问确认。用户确认后，逐个调用 `clear_progress({"session_id":"<目标 session_id>"})`。用户未确认、会话未归档、归档状态无法确认、仍有较新记录或年龄无法判定时，不调用清理工具。
6. 对每个成功清理的 ID 再显式查询 overview，确认 `structuredContent.progress` 为空，并报告已清理、被跳过和无法判定的会话数。不得声称已扫描用户未提供的其他会话。

## 禁止事项

- 不因计划完成、任务完成、重规划、新任务初始化或视图关闭而清理。
- 不把任务实例归档到 `task_history` 当成数据删除请求；归档用于保留同一会话内的历史。
- 不清理活动会话；即使用户确认要删除其中当前任务，也不属于本 skill 的清理范围。
- 不因 Codex 对话显示为历史记录，就推断插件能够识别该状态或自动取得对应的 `session_id`。
