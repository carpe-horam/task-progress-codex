# Regression checks

Host source isolation: `test_shared_service.py` runs real Codex/Cindy bridge forwarding against isolated HTTP, checks per-source lists/tokens/details, restart persistence, explicit legacy registration and cross-source archive rejection. `test_widget_store.py` covers source-write failure and malformed metadata without task mutation or list leakage. Chrome `test_widget_panel.cjs` creates Codex, Cindy and unknown tasks on one daemon and checks separate row counts and archival; `test_cindy_host_archive.cjs` checks explicit binding registration, 100-item batches and retry on old hosts. Unknown legacy records are never inferred to be Codex just because a Cindy binding is missing.

Source registration can also overlap an unknown widget read within one Agent. `test_widget_store.py` registers a source and performs a real title update in the exact gap before the catalogue lock or between the snapshot's two core reads. The unknown catalogue must omit that session, and the old unknown snapshot must reject the newly classified result; the Cindy view must still read it. Both regressions fail against the implementation without the repeated source checks.

Session catalogue: `test_widget_store.py` verifies one row and one count per `session_id`, pagination/search across nested records, and unfinished parallel work when the foreground is complete. `test_widget_panel.cjs` exercises nested record switching, exact historical deep links, historical-title search, foreground changes while its iframe is hidden, and whole-session archival without changing the session total. `test_host_archive.py` also checks that a session archive applies to instances created later, preserving their original execution results. None of these tests deletes tasks or installs the plugin.

Host archive sync: `python3 -B -m unittest discover -s tests -p test_host_archive.py -v` and `node tests/test_cindy_host_archive.cjs` cover one-way archival, startup batching, replay/gap recovery, failures, binding changes, unchanged execution results, history/parallel scope and read-only capabilities. `test_shared_service.py` also verifies real HTTP persistence across daemon restart; `test_widget_panel.cjs` verifies the archived task moves into history in Chrome and remains readable. The Cindy adapter is tested against a host-contract fixture; this does not prove an installed native host has loaded the change.

`node tests/test_cindy_host_archive_review.cjs` additionally injects persistent per-task failure, failed startup batches and lost acknowledgments, then drives the registered 60-second timer to verify fair retries, later-batch progress, next-pass catch-up and legacy-host retry without `sessionStates`. The original source failed three of these checks before the review fixes.

`node tests/test_cindy_host_archive_integration.cjs` connects the real resident adapter to a disposable HTTP service with temporary storage. It checks startup archival, acknowledgment loss after an actual service commit, scheduled retry, adapter restart, unchanged task bytes and archived widget catalogue rows. Host session states remain a contract fixture.

`node tests/test_cindy_host_archive_outbox.cjs` verifies durable enqueue-before-send, restart recovery with active hosts or no `sessionStates`, binding conflicts, storage/cleanup failures, corrupt entries and late PUT acknowledgment. The integration test also launches separate Node processes with a shared temporary KV file and real HTTP archive service to prove offline enqueue survives process exit, active-state restart, lost acknowledgment, idempotent replay and confirmed queue cleanup.

`node --test tests/test_cindy_host_archive_consistency.cjs` adds controlled concurrent triggers, rebinding during a delayed send, cleanup-read failure followed by rebinding, replacement queue records and restart with a stale binding. The integration test additionally performs explicit SIGKILL after enqueue persistence, service commit and cleanup persistence. These are process-crash checks, not power-loss guarantees.

`node --test tests/test_cindy_host_archive_edges.cjs` adds 13 single-Agent boundaries: six invalid acknowledgment forms, failed/late startup reads, binding repair through the same serialized KV writer while enqueue is pending, enqueue-read recovery, committed cleanup with a late reply, queue repair, and progress past a blocked old binding. String/numeric `ok` responses reproduced premature cleanup before strict boolean validation was added.

`node tests/check_cindy_host_archive_fault_coverage.cjs` runs the 19 unmodified boundary/interleaving cases, then loads temporary copies of the real `main.js` with four deliberate faults. Each must fail its intended assertion: truthy success flag, skipped binding check, skipped durable cleanup, and deletion of a replacement record. It verifies the production source is unchanged. `TASK_PROGRESS_TEST_SOURCE` is a test-harness-only source override used by these negative controls; ordinary regression runs use the repository source.

The widget wheel regression computes the intersection of the iframe, scroll container and viewport, and checks `elementFromPoint` before sending wheel input. A clipped bottom-row iframe's geometric center can otherwise hit the footer and falsely report a scrolling regression. `test_cindy_worker_bridge.cjs` also checks the actual Node worker forwards the archive RPC and target IDs through a real subprocess, with a Python echo fixture.

**Scope:** acceptance covers a single Agent, including in-runtime concurrent events and that Agent's crash/restart recovery. Multiple different Agents writing the same KV concurrently are excluded by the user. `test_cindy_host_archive_shared_kv_risk.cjs` retains the historical two-runtime lost-update reproduction as one skipped test; it is neither a passing safety check nor an acceptance blocker. See [consistency review](../docs/protocol/host-archive-sync.md).

`node tests/test_widget_panel.cjs` runs the native widget's canonical HTML shell against a real isolated HTTP service in headless Chrome. It checks the live catalogue, fixed instance selection, unchanged `app.html`, automatic refresh, Excel/HTML downloads, the eight-task limit, selected-only inner scrolling, single/tiled switching, dark/light themes, manual sidebar folding through 320–1024 px resizes and task preservation after closing. `test_widget_store.py` covers current/parallel/archive identity, frozen results, read-only selection, cache invalidation, pagination and corrupt-session warnings. `test_shared_service.py` also checks scoped read-only widget credentials, blocked mutations, Origin/Host validation and expiry. These checks do not launch the user's browser or prove native AppKit behavior; native window and export acceptance is a separate macOS check.

The live workspace regression is `node tests/test_package_distribution_app.cjs`. It creates 16 groups and 128 leaves through the real backend, checks scoped filtering and search, opens the relevant record, switches between outstanding results, and returns from archived history. Set `TASK_PROGRESS_BROWSER_ARTIFACTS` to record the served panel at 320, 390, 768, and 1280 pixels in both host themes.

`node tests/test_dense_packages_app.cjs` covers a single package with 128 tasks, uneven packages with 240/3/5 tasks, and a 1000-task layout stress case at 320, 390, and 1280 pixels in both themes. It checks matrix cell geometry, 10-item global pagination, 24-item historical tree pagination, full-set search and filtering, focus jumps, refresh retention, independent historical pages, and opening an initially empty history tab while a snapshot refresh is in flight. Its screenshots use the production HTML and an isolated backend; they are not native Cindy screenshots.

`node tests/test_task_detail_ux.cjs` covers accepted/resolved, pending review, running, failed, accepted-but-open, rejected, synthesized groups, and archived tasks at 320/390/900 px in both themes. It checks plain default results, hidden raw metadata, preserved failure reasons, and real evidence/attempt/review/title-history disclosures, capturing 48 default views plus 8 expanded-record views. It uses the isolated real backend and a simulated MCP Apps host, not native Cindy. `TASK_PROGRESS_BROWSER_ARTIFACTS` selects its evidence directory.

`node tests/test_workspace_navigation_app.cjs` checks the three workspace tabs, keyboard focus, lazy history, revision records, the leaf progress bar, task status and atomic-task compatibility. `node tests/test_cindy_panel.cjs` regenerates the Cindy core before testing the actual adapter, so stale generated files cannot conceal a shared UI change.

Make `playwright` available through normal Node module resolution or set `NODE_PATH` to an existing package directory. `TASK_PROGRESS_BROWSER_CHANNEL` can select another already-installed Playwright channel; it defaults to `chrome`. No dependency or browser is installed by the tests.

Fixtures use temporary session directories and temporary export files. They never read or modify existing task sessions or Downloads. The browser checks exercise real timers, reordered replies, historical iframe mounts, clear/recreate ordering, and the real export click handler. `validate_exports.py` independently checks the generated workbook using ZIP/XML parsing, including synthesis and retry records.

`test_interaction.cjs` also checks focus, text selection and nested scrolling across automatic and changed-state refreshes, keyboard toggles, retry records, theme changes, 280–900 px layouts, transient failures and delayed replacement cards. Set `TASK_PROGRESS_TEST_ARTIFACTS` to an output directory to retain screenshots. `test_export.cjs` uses the real save handler in a child process with an isolated `Path.home()`; it checks leaf task titles and Unicode filename boundaries. `test_export_river.cjs` saves and opens a real offline report with three current plans, nested tasks, retry/review records and repeated archived task IDs. It verifies collapsed defaults, main-path visibility, nested/bulk/keyboard controls, river/table switching, OLD→NEXT replan provenance, safe literal hostile text, complete table records, 320–1280 px layouts and reduced motion. Readability checks expand a seven-level tree with a long mixed-language title, verify capped indentation and node boundaries, complete status badges on an independent line, distinct direct-child/bottom-level counts, and compact start-only/end-only/missing/cross-day time summaries with raw timestamp tooltips. Attention checks cover fixed semantic colors across all six themes, current-only leaf counts, collapsed parent badges, matching table states and neutral history/cancellation/unrecorded acceptance. Theme checks cover six light palettes, the porcelain-blue default under a dark OS, per-report preference persistence, invalid or unavailable storage and preservation of view/disclosure state. It retains `/tmp/task-progress-export-preview.html` for visual inspection; SQLite-only boundaries are checked by `test_history_loading_app.cjs`. Run browser scripts sequentially; each normally takes less than one minute.

The simulated host captures export-save requests; the backend save function is tested separately. This is not a native Codex host or Excel end-to-end test. Keep generated logs, runtime snapshots and manual audit evidence locally; they are not part of the regression suite or release source.

`test_plan_operations.py` validates isolated running snapshots, idempotent retries, safe dependency/order/group edits, stale and unsafe rejection, old data compatibility and preservation through replanning and task archive. `test_plan_operations_app.cjs` exercises lazy display of snapshots and revisions in Chrome with an isolated server.

`test_app_audit_regressions.cjs` reads the packaged HTML through `resources/read`, verifies manifest version injection, checks linear and failed/cancelled delivery summaries and root acceptance records, freezes archived elapsed time, and replays a fullscreen registration that executes after the real 15-second RPC timeout. Set `TASK_PROGRESS_BROWSER_ARTIFACTS` to retain its screenshots, exported HTML and protocol trace. The backend `test_state_revision_fixes.py` covers persistent initialization keys, linear attempt isolation, and stale mode registrations; `test_hook_runtime.py` checks both hooks with a configured Python and an otherwise empty PATH.

`test_shared_service.py` uses a real isolated HTTP daemon to verify concurrent clients, identical JSON-RPC IDs, session isolation, initialization idempotency, authentication, duplicate-daemon exclusion, and graceful/crash restart persistence. `test_service_manager.py` uses temporary homes, real loopback health fixtures, and a fake launchctl runner to test install/upgrade rollback and ownership checks without modifying the user's service. `test_shared_service_app.cjs` connects the real browser UI through HTTP, exercises two chats and fullscreen restoration, and confirms every response comes from one daemon. Set `TASK_PROGRESS_BROWSER_ARTIFACTS` to retain its screenshot and result. The browser host is simulated; native Codex transport acceptance is recorded separately in the review evidence.

For native transport acceptance, run `python3 -B tests/check_codex_http_transport.py --codex /absolute/path/to/codex`. It starts two disposable app-server clients and an isolated HTTP daemon, discovers tools, and reads the UI resource without creating chats or sending model turns. Responsibility regressions cover planned executors, explicit reassignment, post-spawn agent binding, result submission, separate main-session acceptance/rejection, dependency gates, and retry invalidation. `test_delegation_policy.py` runs the skill's published JSON examples through public JSON-RPC wire responses against isolated backend state, including sequential complex work delegated to subagents. `test_responsibility_app.cjs` verifies the actual app and offline exports distinguish pending review, rejected work, accepted-but-open reports, resolved results, and legacy records without inventing acceptance history. These checks validate workflow declarations and transitions; they do not authenticate Codex callers or control work performed through other tools.

`test_history_loading_app.cjs` verifies compact polling, on-demand full history, exact snapshot cache binding, delayed full-response rejection, complete HTML/XLSX exports, fail-closed export on unavailable current JSON history, warnings on bounded or unavailable SQLite excerpts, and separate JSON/SQLite read-only provenance. All fixtures and exports are isolated. The SQLite display preserves old status values and does not infer current-protocol acceptance.

Historical running-duration checks install a pre-protocol snapshot into a separate private fixture session and verify task bytes stay unchanged while browsing. Live task replacement fixtures finish their old goal first; they do not use replacement reasons to bypass running-attempt guards. Browser fixture processes isolate both JSON sessions and the legacy SQLite path (or HOME for the HTTP daemon). SQLite-only exports are checked to contain no invented current plan, round, pending status or 0/0 progress.

`test_request_queue.py` covers independent instances, FIFO activation, registration and activation retries, original request/context preservation, cancellation, stale writes, atomic activation failure, and controlled thread interleavings with delayed responses. `test_request_queue_app.cjs` verifies real pending submissions and dependency blocking, accepted progress versus root synthesis, queue visibility, parallel roots, foreground protection, and archived-origin versus current-return guidance. These checks do not prove host-side automatic scheduling; request queues and recovery context are currently outside the HTML/XLSX export scope.

Parallel roots now render directly in the task network. `test_parallel_roots_app.cjs` verifies sibling placement, instance-scoped duplicate node IDs, stable expansion, independent review states, foreground activation, cached payload placeholders and cancelled requests. The request-queue browser test uses the same inline roots instead of a preview switch. Backend projection tests ensure all roots share one captured revision and that reads do not change stored nodes or include recursive history.

Resolved parallel roots move into task history after every node is resolved and root synthesis is complete. Open, failed and cancelled work stays visible until an explicit parent closure review or accepted handoff closes it; original outcomes stay unchanged. `test_request_queue.py` covers frozen acceptance snapshots, explicit retry/reappearance, stale writes, read-only projection of old completed instances, history pagination and deduplication across foreground activation. `test_parallel_archive_app.cjs` verifies lazy history, independent disclosure/export keys for repeated acceptances of the same instance, compact refresh and complete HTML/XLSX evidence. Instances remain addressable by their original ID; only an explicit retry may reopen a completed instance. These are isolated backend and Chrome checks, not native Codex host acceptance.

`test_handoff_closure.py` covers pending-to-accepted handoff reconciliation, a target in an archived instance's old epoch, a cancelled source leaf with no attempt, rejected/stale/self/cyclic/incomplete mappings, source result bindings, cancellation closure continue/accept decisions, unchanged nodes, frozen retry archives, unresolved dependency protection and selective audit receipts/queries. Run it with `python3 -m unittest discover -s tests -p test_handoff_closure.py -v`. `test_handoff_closure_app.cjs` runs the real app and isolated server in Chrome, checks two resolved plus one cancelled parent waiting for synthesis, then handoff/closure history and complete HTML/XLSX acceptance evidence. No live session or shared service is involved.

The request-queue browser test also checks collapsed context with a visible queue count, concise task rows retaining role, bound agent, model and reasoning effort, a result summary on task expansion with separately collapsed execution/binding/review/evidence details, full records on demand, refresh persistence, and disclosure isolation when the task instance changes.

Selective-query checks use raw wire responses, not a helper that expands receipts into snapshots. `test_selective_query_wire.py` covers overview/tree/tasks/records/context/history/full, pagination and revision mismatch, complete selected-instance records, compact peers, and paginated ready dependencies. `test_tool_response_performance.py` measures serialized UTF-8 response bytes on fixed synthetic fixtures; it does not measure model tokens or native Codex message-expansion latency. Mutation and render receipts must not contain task trees, summaries, evidence, or request bodies.

`test_selective_view_app.cjs` checks the app-only read path, bootstrap loading, receipt refresh and identity rows. `test_record_loading_app.cjs` checks lazy record cache identity, concurrent requests, late peer replies and retry after failure. `test_auto_display.py` and `test_auto_display_app.cjs` cover one-time latest render intent consumption, concurrent mounts, existing fullscreen leases, teardown, close/poll/replay, explicit reopening, initialize/bootstrap ordering, capability refusal and actual-mode replies. `test_dynamic_numbering_app.cjs` verifies multi-level numbering, reversed prerequisites, current child-order/dependency changes, inserted prerequisites, inherited group and cross-branch constraints, valid interleaving branches, same-ID parallel isolation, hierarchy changes, actual backend replanning/history, and a real backend insertion with its badge and reason. `test_dsh_bundle.py` covers the DeepSeekRuntime (dsh) packaging in `plugins/task-progress/dsh`. Packaging cases assert that the bundle version follows `.codex-plugin/plugin.json`, that it ships one `cordis.patch.yml` row for its own package, that no `@deepseek-ai/*` import or dependency exists (a linked profile bundle cannot resolve those in this dsh version), and that `app.html`, `server.py` and the skill bodies are referenced from the Codex plugin instead of being copied. Behaviour cases run the real ES modules through Node: JSON Schema `required[]` becomes `required: true` in the DSH parameter dialect, unknown `anyOf` branches keep their type, server text becomes the tool value and rendered content, server-side `isError` surfaces as a tool error, the shipped skills register with a directory `resourceBase` and stripped frontmatter, and the exported `createPanelRoute` serves `app.html` at 200 with the version placeholder replaced, returns `404` for other paths and relays JSON-RPC — preserving ids, answering notifications with `202` and mapping relay failures to `502`. Nothing here starts Python, touches `~/.cache/task-progress` or requires an installed dsh profile, so it does not verify the live card, the panel inside the Web GUI or Codex-side installation.
